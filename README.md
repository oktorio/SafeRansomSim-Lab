# SafeRansomSim-Lab

A deliberately constrained, non-propagating ransomware-behavior simulator for cybersecurity education, blue-team detection engineering, incident response, cryptography learning, and recovery testing.

> **THIS SOFTWARE IS A NON-PROPAGATING EDUCATIONAL RANSOMWARE SIMULATOR. IT IS DESIGNED TO OPERATE ONLY ON DISPOSABLE FILES CREATED INSIDE ITS OWN SANDBOX.**

## Safety model

The simulator is intentionally designed so it cannot be pointed at an arbitrary directory. Its only file-processing target is hard-coded to:

```text
./ransomware_lab/test123/
```

Core safeguards:

- Dry-run is the default behavior.
- Real simulation requires the explicit `--simulate` flag.
- A manually created `ransomware_lab/AUTHORIZED_LAB.txt` containing exactly `I_AUTHORIZE_SAFE_RANSOMWARE_SIMULATION` is required before any modifying simulation/recovery/cleanup action.
- Only files generated by `--setup`, recorded in the simulator manifest, and carrying the lab marker are eligible.
- Canonical-path containment checks are performed before file operations.
- Symlinks/reparse points and path traversal are rejected.
- Maximum 100 files, 5 MiB per file, 100 MiB total, recursion depth 3.
- A `ransomware_lab/STOP_SIMULATION` kill-switch is checked before each simulated encryption operation.
- No persistence, propagation, lateral movement, privilege escalation, C2, credential theft, exfiltration, security-tool disabling, backup deletion, or evasion is implemented.
- The simulator performs no network activity.

## Requirements

- Python 3.11+
- `cryptography`
- `pytest` for tests

Install dependencies:

```bash
python -m pip install -r requirements.txt
```

## Quick start

### 1. Create disposable lab files

```bash
python simulator.py --setup
```

### 2. Explicitly authorize the lab

Copy the example authorization file and keep the exact authorization phrase:

```bash
cp ransomware_lab/AUTHORIZED_LAB.example.txt ransomware_lab/AUTHORIZED_LAB.txt
```

On Windows PowerShell:

```powershell
Copy-Item ransomware_lab/AUTHORIZED_LAB.example.txt ransomware_lab/AUTHORIZED_LAB.txt
```

### 3. Inspect the dry run

```bash
python simulator.py --dry-run
```

Running `python simulator.py` with no mode also performs a dry run.

### 4. Run the controlled simulation

```bash
python simulator.py --simulate
```

Eligible disposable files become `.SIMULATED_LOCKED` files only inside `ransomware_lab/test123/`. The original disposable content is first copied to the local backup area and verified.

### 5. Recover and verify

```bash
python simulator.py --recover
```

Recovery decrypts the simulator-generated files and compares their SHA-256 hashes with the original manifest.

### Other commands

```bash
python simulator.py --status
python simulator.py --simulate-initial-access
python simulator.py --cleanup
```

`--simulate-initial-access` does **not** deliver a malicious attachment. It records a harmless `SIMULATED_EMAIL_ATTACHMENT_EXECUTION` telemetry event and then invokes the same constrained local simulation.

## Cryptographic demonstration

The lab uses **AES-256-GCM** through the high-level `cryptography` library.

- AES is the Advanced Encryption Standard.
- 256 refers to the 256-bit key size.
- GCM provides authenticated encryption, so tampering is detectable.
- A fresh random 96-bit nonce is generated for each encrypted test file.
- Nonce reuse with the same GCM key is unsafe and is explicitly avoided.
- No custom cryptography is implemented.

The demonstration recovery key is stored only at:

```text
./ransomware_lab/recovery/demo_key.bin
```

The runtime recovery directory is excluded from Git.

## Telemetry

Structured JSONL logs are written under `ransomware_lab/logs/`. Example event types include:

- `SIMULATION_STARTED`
- `AUTHORIZATION_VERIFIED`
- `FILE_DISCOVERED`
- `FILE_ENCRYPTION_STARTED`
- `FILE_ENCRYPTION_COMPLETED`
- `RANSOM_NOTE_CREATED`
- `RECOVERY_STARTED`
- `FILE_RECOVERED`
- `HASH_VERIFICATION_SUCCESS`
- `HASH_VERIFICATION_FAILURE`
- `SIMULATION_STOPPED`
- `SIMULATED_EMAIL_ATTACHMENT_EXECUTION`

See [`docs/detection-engineering.md`](docs/detection-engineering.md) for defensive detection ideas.

## Safety testing

Run:

```bash
pytest -q
```

The tests focus on containment, authorization, recovery integrity, and kill-switch behavior.

## Scope limitations

This project deliberately sacrifices offensive realism for containment, reversibility, observability, and defensive learning value. It is not intended to reproduce a deployable ransomware payload.
